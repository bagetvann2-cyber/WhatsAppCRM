# WhatsApp CRM

Платформа WhatsApp Business для казахстанского бизнеса. ТЗ — `docs/TZ-WhatsApp-CRM.md`.

Сейчас в репозитории вертикальный срез: приём вебхука от Meta → запись в PostgreSQL →
показ диалога в браузере → ответ оттуда. План — `docs/plans/2026-08-16-whatsapp-vertical-slice.md`.

## Стек

Next.js 16 (App Router, TypeScript) · Prisma 7 + PostgreSQL 17 · Vitest · SSE для живых обновлений.

## Запуск разработки

```powershell
cd "C:\Users\BagetPC_2\Desktop\WhatsAppCRM"
npm run dev
```

Приложение на `http://localhost:3000`. Вложения, отписка, автоответ и ИИ-бот
обрабатываются отдельным воркером (см. «Очередь входящих» ниже) — без него
входящие сохраняются, но ответом никто не отвечает:

```powershell
npm run worker
```

Тесты (поднимают реальную локальную базу):

```powershell

```

## Переменные окружения

Все секреты — в `.env.local`, файл в `.gitignore` и в git не попадает.

| Переменная | Откуда взять |
|---|---|
| `DATABASE_URL` | локальный Postgres, база `whatsapp_crm_dev` |
| `WHATSAPP_APP_SECRET` | Meta → App settings → Basic → App secret |
| `WHATSAPP_TOKEN` | Meta → WhatsApp → API Setup → Temporary access token |
| `WHATSAPP_PHONE_NUMBER_ID` | Meta → WhatsApp → API Setup → Phone number ID |
| `WHATSAPP_VERIFY_TOKEN` | придумывается произвольно, вводится в настройках вебхука |
| `NEXT_PUBLIC_WHATSAPP_APP_ID` | Meta App → App settings → Basic → App ID (публичный, идёт в браузер) |
| `NEXT_PUBLIC_WHATSAPP_CONFIG_ID` | Meta App → WhatsApp → Embedded Signup → Configuration (публичный) |
| `GRAPH_API_VERSION` | версия из примера curl в консоли Meta, например `v22.0` |
| `MEDIA_DIR` | необязательно, куда класть копии вложений; по умолчанию `storage/media` |
| `MEDIA_MAX_MB` | необязательно, потолок размера файла; по умолчанию 32 |
| `ANTHROPIC_API_KEY` | ключ Claude для ИИ-помощника |
| `OPENAI_API_KEY` | ключ ChatGPT (platform.openai.com/api-keys) для ИИ-помощника на нашем счёте |
| `GEMINI_API_KEY` | ключ Gemini (aistudio.google.com/apikey); нужен ключ платного проекта: на бесплатном уровне Google может использовать переписку |
| `RESEND_API_KEY` | ключ Resend для писем подтверждения почты; без него регистрация не сработает |
| `EMAIL_FROM` | необязательно, адрес отправителя; по умолчанию `onboarding@resend.dev` (шлёт только на почту аккаунта Resend) |

Prisma читает `.env.local` через `prisma.config.ts` — отдельный `.env` не нужен.

## Подключение вебхука Meta

Meta стучится по HTTPS, поэтому localhost наружу отдаётся туннелем:

```powershell
cloudflared tunnel --url http://localhost:3000
```

Выданный адрес вида `https://что-то.trycloudflare.com` вписывается в
Meta → WhatsApp → Configuration → Webhook:

- **Callback URL:** `https://что-то.trycloudflare.com/api/webhook`
- **Verify token:** значение `WHATSAPP_VERIFY_TOKEN`
- в блоке Webhook fields включить подписку **messages**

Адрес туннеля меняется при каждом перезапуске `cloudflared` — Callback URL придётся
переподключать. Временный токен Meta живёт 24 часа; постоянный выпускается только
в верифицированном Business Manager заказчика.

## Подключение номера (Embedded Signup)

Самостоятельное подключение владельцем — раздел «Каналы» в кабинете. Чтобы кнопка
заработала, в Meta App нужны:

1. Продукт **WhatsApp** и **Facebook Login for Business**.
2. Домен кабинета в списке **Valid OAuth Redirect URIs** (App settings → Basic →
   Add Platform → Website, плюс App Domains).
3. **Configuration** в разделе WhatsApp → Embedded Signup — её id идёт в
   `NEXT_PUBLIC_WHATSAPP_CONFIG_ID`.

Без верифицированного Business Manager Meta ограничивает подключение (до 10 новых
клиентов за 7 дней в тестовом режиме) — этого достаточно для пилота, но не для
продажи всем подряд.

## Что уже работает

- проверка подписи `x-hub-signature-256` от Meta;
- GET-верификация и POST-приём вебхуков, идемпотентность по `wamid`;
- разбор входящих сообщений и статусов доставки;
- список диалогов, переписка, отправка ответа, обновление без перезагрузки;
- блокировка свободного ответа по истечении 24-часового окна;
- кабинеты компаний, роли и приглашения по ссылке;
- шаблоны с модерацией Meta, рассылки с отчётом, контакты с метками и импортом;
- автоответы: приветствие и нерабочие часы;
- ИИ-помощник на Claude API с передачей диалога оператору;
- ответственный за диалог: вкладки «Все / Мои / Свободные», отметка в списке;
- отписка от рассылок по слову «стоп» и вручную оператором;
- отчёты: рабочий стол числами и нагрузка команды;
- тарифы, пробный период, баланс на сообщения и счета;
- вложения: приём фото, видео, голосовых и документов, отправка файла оператором;
- очередь pg-boss и воркер: обработка входящих (вложение, отписка, автоответ, ИИ-бот)
  не задерживает ответ Meta на вебхук;
- ИИ-бот собирает заказ из переписки в настраиваемые поля, оператор подтверждает
  на `/orders`, выгрузка в CSV;
- самостоятельное подключение номера через Meta Embedded Signup, статус и качество
  номера — раздел «Каналы».

### Вложения

Meta хранит присланный файл 30 дней, поэтому копия сразу скачивается в `MEDIA_DIR`
(каталог в `.gitignore`). Отдаёт её только `/api/media/<id>` с проверкой компании:
прямых ссылок на файлы нет. Ответ помечен `Content-Security-Policy: sandbox` —
скрипт внутри присланного SVG или HTML не выполнится на домене кабинета.

Не скачалось — сообщение всё равно сохраняется, а файл догружается при первом
открытии: идентификатор у Meta остаётся в базе.

### Ответственный за диалог

Назначение мягкое: оно показывает, кто взял клиента, но не запрещает отвечать
остальным — оператор ушёл на обед, а клиент ждать не должен. Руководитель
распоряжается очередью целиком, оператор берёт свободный диалог и отпускает свой,
чужой отобрать не может. Уволили сотрудника — его диалоги возвращаются в общую
очередь, а не исчезают вместе с ним.

Диалог, который ИИ-помощник вернул человеку, помечен в списке «нужен человек»,
пока его никто не взял.

### Отписка от рассылок

Клиент пишет «стоп» (или «отписаться», `stop`, `тоқта`) — контакт помечается
отписавшимся и получает одно подтверждение. Ни автоответ, ни ИИ-помощник в этот
момент не вмешиваются. Отпиской считается всё сообщение целиком: «стоп, а сколько
стоит?» — это вопрос, а не отказ.

Запрет касается только рекламы: **MARKETING**-шаблоны отписавшимся не уходят,
**UTILITY** — уходят, потому что подтверждение записи клиент не отменял. Если
отписка случилась уже после создания рассылки, получатель помечается `SKIPPED`,
а не ошибкой — иначе автостоп счёл бы это сбоем отправки.

### Тарифы и баланс

Тарифы, цены и лимиты лежат в таблице `Plan`, а не в коде: Meta меняет правила
чаще, чем удобно выкатывать релиз ради новой цифры. Значения по умолчанию —
из раздела 9 ТЗ, заказчик правит их в базе.

Подписка оплачивает интерфейс, баланс — сами сообщения. Списание идёт **по факту
доставки**, как берёт деньги Meta: статус `delivered` из вебхука снимает цену
категории с баланса, повторный вебхук второй раз не спишет. Перед запуском
рассылки баланс проверяется целиком — оборванная на середине рассылка хуже
отложенной.

Пробный период начинается с **первого живого сообщения**, а не с регистрации:
клиент не сжигает бесплатные дни, пока разбирается с Meta.

**Приём оплаты — заглушка.** Счёт создаётся и ждёт денег; Kaspi и банковский
платёж вызовут `markInvoicePaid` — остальной код не изменится. Кнопка «Отметить
оплаченным» есть только вне production.

## Демо-стенд

Кабинет для показа заказчику: **https://crm.neiroflow.kz** (VPS `95.85.233.195`,
каталог `/var/www/whatsappcrm`, процесс pm2 `crm` на порту 4100, база
`whatsapp_crm` в тамошнем PostgreSQL 16). Секреты — в `/var/www/whatsappcrm/.env.local`
на сервере, в репозиторий не попадают.

Наполнен демо-данными: стоматология, семь диалогов с вложениями, три шаблона,
рассылка с отчётом, оплаченный тариф и баланс.

### Обновить стенд

```bash
bash scripts/deploy.sh
```

Сборка идёт на рабочей машине и заливается готовой: на сервере 2 ГБ памяти на
пять приложений, и `next build` там способен увести в OOM соседние проекты.

Одна тонкость, из-за которой стенд падает при ручной выкладке. Next выносит
внешние пакеты (`@prisma/client`, `pg`) в `.next/node_modules` под именами с
хешем сборки, но в `standalone` их не кладёт — на рабочей машине они находятся
поиском вверх по дереву каталогов, а на сервере искать негде, и приложение
падает с `Cannot find module '@prisma/client-<хеш>/runtime/client'`. Скрипт
пересоздаёт эти ссылки при каждой выкладке: хеш меняется от сборки к сборке.

### Миграции и данные на стенде

Порт PostgreSQL наружу закрыт, поэтому база правится через SSH-туннель —
на сервере не нужны ни Prisma CLI, ни `tsx`:

```bash
ssh -f -N -L 55432:127.0.0.1:5432 root@95.85.233.195
DATABASE_URL="postgresql://whatsapp_crm:<пароль>@127.0.0.1:55432/whatsapp_crm" npx prisma migrate deploy
```

Пароль базы лежит в `DATABASE_URL` внутри `/var/www/whatsappcrm/.env.local`.

Демо-данные заливаются тем же способом, но вложения скрипт пишет на ту машину,
где запущен, — папку потом надо перенести в `/var/www/whatsappcrm/storage/media`.

### Стенд обязан работать по HTTPS

Сборка `standalone` жёстко ставит `NODE_ENV=production`, поэтому сессионная
cookie уходит с флагом `Secure`. По HTTP браузер такую cookie молча
выбрасывает: форма входа срабатывает, а следующий переход выкидывает на
`/login` — и выглядит это как поломка авторизации, а не как отсутствие
сертификата. Поэтому nginx отвечает на HTTP редиректом 301, и открыть кабинет
без сертификата нельзя в принципе.

### Вебхук Meta на стенде

Постоянный адрес вместо туннеля `cloudflared`, переподключать после каждого
перезапуска больше не нужно:

- **Callback URL:** `https://crm.neiroflow.kz/api/webhook`
- **Verify token:** значение `WHATSAPP_VERIFY_TOKEN` из `.env.local` на сервере

Временный токен Meta живёт 24 часа: чтобы живая переписка на стенде не отвалилась
к следующему дню, нужен постоянный токен системного пользователя. Он выпускается
в бизнес-портфеле и верификации бизнеса не требует.

## Особенности локальной отладки

**После миграции базы перезапускайте `npm run dev`.** Экземпляр Prisma кэшируется в
`globalThis`, чтобы горячая перезагрузка не плодила подключения к Postgres. Побочный эффект:
после `prisma migrate` и `prisma generate` в памяти остаётся клиент, собранный по старой схеме,
и обращение к новой таблице падает с `Cannot read properties of undefined`. Перезапуск лечит.


Колонка `windowExpiresAt` хранится без часового пояса, а Node читает её как UTC.
Если менять окно вручную через `psql`, время задавать явно в UTC:

```powershell
$env:PGPASSWORD='postgres'
$sql = @'
UPDATE "Conversation" SET "windowExpiresAt" = (NOW() AT TIME ZONE 'UTC') - INTERVAL '1 hour';
'@
$sql | & "C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -h localhost -d whatsapp_crm_dev -q
```
